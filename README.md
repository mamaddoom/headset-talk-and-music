# رایدتاک (RideTalk) — اینترکام آفلاین موتورسواری

اپلیکیشن اندرویدی سبک برای اینکه دو (یا چند) موتورسوار بدون اینترنت و فقط با **هات‌اسپات یکی از گوشی‌ها** با هندزفری بلوتوثی خودشان با هم صحبت کنند و **موزیک مشترک** همزمان گوش بدهند.

- بدون اینترنت، بدون سرور، بدون ثبت‌نام
- صحبت دوطرفه همزمان (فول‌داپلکس) با کدک Opus، تأخیر هدف کمتر از ۱۵۰ میلی‌ثانیه
- حالت «میکروفن باز» با تشخیص خودکار صدا و حالت «فشار برای صحبت» (دکمهٔ بزرگ روی صفحه + دکمهٔ هندزفری)
- پخش موزیک از گوشی برای همه، با کم شدن خودکار صدای موزیک وقتی کسی صحبت می‌کند
- با صفحهٔ خاموش کار می‌کند (سرویس پیش‌زمینه)
- حجم APK زیر ۱ مگابایت، تنها وابستگی: کتابخانهٔ Opus جاوای خالص (Concentus)
- رابط کاربری فارسی/انگلیسی با دکمه‌های بزرگ برای استفاده با دستکش

## دانلود و نصب

1. به بخش [Releases](https://github.com/mamaddoom/headset-talk-and-music/releases) همین مخزن بروید (از مرورگر گوشی).
2. آخرین فایل `RideTalk-1.0.X.apk` را دانلود کنید.
3. روی فایل بزنید و نصب کنید (اگر پرسید، اجازهٔ «نصب از منابع ناشناس» را برای مرورگر بدهید).
4. همین کار را روی گوشی دوم هم انجام دهید.

هر بار که کدی push شود، GitHub Actions خودکار یک APK امضاشدهٔ جدید می‌سازد و در Releases می‌گذارد. نسخه‌های جدید روی نسخهٔ قبلی نصب می‌شوند (نیازی به حذف نیست).

## راه‌اندازی در اولین استفاده (هر دو گوشی)

1. برنامه را باز کنید، «شروع اینترکام» را بزنید و به میکروفن، بلوتوث و اعلان‌ها اجازه بدهید.
2. در کارت «تنظیمات و پایداری»:
   - **باتری: بدون محدودیت** را بزنید و تأیید کنید.
   - **اجرای خودکار** را بزنید و رایدتاک را روشن کنید.
   - اسم خودتان را بنویسید (به نفر دیگر نشان داده می‌شود).
3. در صفحهٔ برنامه‌های اخیر، رایدتاک را **قفل** کنید (روی کارت برنامه نگه دارید ← قفل).

### نکات مخصوص گوشی‌های شما

| | OPPO A98 5G (ColorOS) | Redmi Note 14 Pro 5G (HyperOS) |
|---|---|---|
| باتری | تنظیمات ← باتری ← رایدتاک ← «اجازهٔ فعالیت در پس‌زمینه» | تنظیمات ← برنامه‌ها ← رایدتاک ← صرفه‌جویی باتری ← «بدون محدودیت» |
| اجرای خودکار | «اجرای خودکار» را روشن کنید | «Autostart» را روشن کنید |
| هات‌اسپات | گزینهٔ «خاموش شدن خودکار هات‌اسپات» را خاموش کنید | — |
| وای‌فای | — | اگر وای‌فای به دیتای موبایل سوییچ می‌کند «دستیار وای‌فای» را خاموش کنید |

## استفاده هنگام رانندگی

1. هندزفری بلوتوثی هر نفر را به گوشی خودش وصل کنید.
2. **گوشی A:** هات‌اسپات را روشن کنید (دکمهٔ «هات‌اسپات» در برنامه شما را به تنظیماتش می‌برد). اینترنت لازم نیست.
3. **گوشی B:** با وای‌فای به هات‌اسپات گوشی A وصل شوید (دکمهٔ «وای‌فای»). اگر گوشی گفت «این شبکه اینترنت ندارد»، «متصل بماند» را بزنید.
4. در **هر دو گوشی** «شروع اینترکام» را بزنید. در چند ثانیه وضعیت سبز می‌شود: «متصل · ۱ نفر».
5. گوشی را در جیب بگذارید و صفحه را خاموش کنید. همه‌چیز ادامه پیدا می‌کند.

اگر ارتباط قطع شود (مثلاً از هم دور شدید)، به‌محض برگشتن در بُرد وای‌فای خودکار دوباره وصل می‌شود؛ نیاز به هیچ کاری نیست.

### حالت‌های میکروفن

- **میکروفن باز:** هر وقت حرف بزنید صدا ارسال می‌شود. «حساسیت تشخیص صدا» را طوری تنظیم کنید که صدای باد و موتور میکروفن را باز نکند (نوار «سطح میکروفن» کمک می‌کند). دکمهٔ هندزفری میکروفن را قطع/وصل می‌کند.
- **فشار برای صحبت:** دکمهٔ بزرگ زرد را نگه دارید. دکمهٔ هندزفری یک بار = شروع صحبت، بار دوم = پایان.
  > بعضی هندزفری‌ها در حالت مکالمه دکمه را به‌جای برنامه به «پاسخ تماس» می‌فرستند؛ در آن صورت از دکمهٔ اعلان یا صفحه استفاده کنید.

### موزیک مشترک

1. در گوشی‌ای که آهنگ‌ها رویش است «انتخاب آهنگ‌ها» را بزنید و یک یا چند فایل (mp3, m4a, ogg, flac, wav …) انتخاب کنید.
2. ▶ را بزنید. آهنگ برای همه پخش می‌شود و هر نفر بلندی موزیک را در گوشی خودش تنظیم می‌کند.
3. وقتی کسی صحبت می‌کند موزیک خودکار کم می‌شود (قابل خاموش کردن).
4. اگر یکی از دو نفر موزیک را کمی زودتر می‌شنود (هندزفری‌ها تأخیر متفاوت دارند)، در گوشی **همان نفر** «تأخیر همزمانی» را کمی زیاد کنید.

> ⚠️ **محدودیت بلوتوث:** میکروفن هندزفری فقط در حالت «تماس» (پروفایل SCO) کار می‌کند که تک‌کاناله و ۱۶ کیلوهرتز است. پس وقتی «استفاده از میکروفن هندزفری» روشن است، موزیک کیفیت صدای تماس تلفنی دارد. این محدودیت خود بلوتوث است، نه برنامه (اینترکام‌های سخت‌افزاری مثل Cardo و Sena هم همین‌طورند).
> اگر می‌خواهید موزیک **استریو با کیفیت کامل** بشنوید، این گزینه را خاموش کنید: صدای همراه را همچنان می‌شنوید ولی خودتان صدا ارسال نمی‌کنید.

### پروتکل (UDP، پورت 47800، little-endian)

<div dir="ltr">

| offset | size | field |
|---|---|---|
| 0 | 2 | magic `"RT"` |
| 2 | 1 | version = 1 |
| 3 | 1 | type: 1 BEACON · 2 VOICE · 3 MUSIC · 4 BYE |
| 4 | 4 | sender id (random per session) |
| 8 | 4 | sequence number |
| 12 | … | payload |

- **BEACON** (1/s, broadcast + unicast to gateway & peers): `flags u8` (talking, music) · `name` (len u8 + UTF-8, ≤40 B) · `music title` (len u8 + UTF-8, ≤120 B)
- **VOICE** (50/s while talking): one Opus packet — 16 kHz mono, 20 ms, 24 kbit/s VBR, in-band FEC (~60 B)
- **MUSIC** (100/s while playing): raw PCM16 — 32 kHz stereo, 10 ms = 1280 B (fits one MTU, ~1.3 Mbit/s)
- **BYE**: sent on stop so the other side drops us immediately

</div>

### چرا این تصمیم‌ها؟

- **UDP و کشف دوطرفه:** فرقی نمی‌کند کدام گوشی هات‌اسپات باشد؛ هر دو هر ثانیه بیکن می‌فرستند و هر کس بیکن دیگری را شنید او را اضافه می‌کند. قطع و وصل خودکار است.
- **قفل کردن سوکت روی وای‌فای:** گوشی‌ای که به هات‌اسپات بدون اینترنت وصل است، دیتای موبایل را مسیر پیش‌فرض نگه می‌دارد و بسته‌ها به‌جای وای‌فای به LTE می‌روند. برنامه شبکهٔ وای‌فای را درخواست می‌کند و سوکت را به آن می‌بندد؛ این مهم‌ترین دلیل «وصل نمی‌شود» در برنامه‌های مشابه است.
- **WifiLock با حالت LOW_LATENCY:** صرفه‌جویی انرژی وای‌فای بسته‌ها را دسته‌ای تحویل می‌دهد و ۱۰۰+ میلی‌ثانیه لگ می‌سازد؛ این قفل جلویش را می‌گیرد.
- **Opus برای صدا، PCM خام برای موزیک:** Opus با FEC و PLC در برابر گم‌شدن بسته‌ها مقاوم است و فقط ۲۴ کیلوبیت می‌خواهد. برای موزیک، پهنای باند هات‌اسپات (ده‌ها مگابیت) آن‌قدر زیاد است که فشرده‌سازی فقط CPU و تأخیر اضافه می‌کرد.
- **همزمانی موزیک:** گوشی پخش‌کننده بستهٔ موزیک خودش را هم از همان بافر ۱۰۰ میلی‌ثانیه‌ای عبور می‌دهد که گوشی مقابل؛ پس هر دو بستهٔ یکسان را در یک لحظه پخش می‌کنند.
- **بافر لرزش (jitter) تطبیقی:** اگر بسته‌ها دیر برسند بافر بزرگ می‌شود و وقتی لینک پایدار شد دوباره کوچک می‌شود. سکوتِ بین حرف‌ها اشتباهی «لرزش» حساب نمی‌شود.

## ساخت از سورس

نیازی به کامپیوتر نیست؛ GitHub Actions (`.github/workflows/android.yml`) با هر push:
1. تست‌های واحد (پروتکل، بافر لرزش، DSP، کدک) را اجرا می‌کند،
2. APK نسخهٔ release را با R8 کوچک و امضا می‌کند،
3. آن را به‌صورت Artifact و GitHub Release منتشر می‌کند.

روی کامپیوتر: `./gradlew testDebugUnitTest assembleRelease` (JDK 17 و Android SDK 35).

### کلید امضا

اگر Secretهای زیر را در Settings ← Secrets and variables ← Actions اضافه نکنید، Actions یک کلید می‌سازد و در cache نگه می‌دارد تا نسخه‌های بعدی روی هم نصب شوند. Cache اگر ۷ روز استفاده نشود پاک می‌شود و هر شاخه cache جدا دارد؛ در آن صورت یک بار برنامه را حذف و دوباره نصب کنید. برای کلید دائمی:

<div dir="ltr">

```bash
keytool -genkeypair -keystore release.jks -alias ridetalk -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.jks   # → RIDETALK_KEYSTORE_BASE64
```

Secrets: `RIDETALK_KEYSTORE_BASE64`, `RIDETALK_KEYSTORE_PASSWORD`, `RIDETALK_KEY_ALIAS`, `RIDETALK_KEY_PASSWORD`

</div>

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| «در جستجو…» تمام نمی‌شود | مطمئن شوید گوشی B واقعاً به هات‌اسپات A وصل است. در خط «این گوشی: …» هر دو باید IP مثل `192.168.x.x` یا `10.x.x.x` با سه عدد اول یکسان داشته باشند. VPN را خاموش کنید. |
| صدا از بلندگوی گوشی می‌آید | هندزفری را قبل از «شروع» وصل کنید یا یک بار توقف/شروع بزنید. |
| با خاموش شدن صفحه قطع می‌شود | بخش «راه‌اندازی در اولین استفاده» را کامل انجام دهید (باتری + اجرای خودکار + قفل در اخیرها). |
| صدای باد میکروفن را باز می‌کند | حساسیت تشخیص صدا را کم کنید یا از «فشار برای صحبت» استفاده کنید. استفاده از اسفنج بادگیر روی میکروفن هندزفری خیلی کمک می‌کند. |
| موزیک کیفیت پایینی دارد | طبیعی است (محدودیت SCO)؛ بخش موزیک مشترک را ببینید. |
